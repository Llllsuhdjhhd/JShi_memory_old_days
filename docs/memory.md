# 记忆写入与存储

最近更新：2026-11-16（北京时间）。本副本恢复完整长事件，保留后续通用修复；详见[恢复说明](long-events-restoration.md)。

默认 `memory_refinement.enabled=false`。边界模型先按语义解交织，正常事件范围为
`event_min_chars <= L < event_min_chars * event_len_factor`，默认 2000 ≤ L < 3000 个 Unicode 字符（空格、标点也计数）。
短于 2000 字的内容保留在未封存缓冲中等待后续；字数不能成为合并不相关事项的依据。
封存时立即生成多级摘要、对象事实和情绪，原文 L0 完整保留。
默认不运行 90/365 天定龄提炼，不再把新经历默认切成约 300 字的轻量事件。

闲置、显式强制保存和超长兜底允许短于正常下限；强制保存标记 `truncated`，不冒充语义闭合。
超长分组及超长单句使用现有有界拆分，单条小于 3000 字；拆分保留来源信息。
同一来源的重复投递在完整事件模式下也按来源片段去重，包括尚未封存与已经封存的材料。

[分阶段记忆提炼](multistage-memory-refinement.md) 代码保留为显式可选模式，其 100/300/500 字规则、
跨时间段短片段封存及定龄聚合不会在默认长事件路径自动启用。
来源日期、段级对象和历史对话对象信息仍随输入、缓冲和已封存事件保存。
长事件边界提示也包含逐句来源时间；未知时间明确标记，时间标签不进入原文或字数。
模型根据原话判断跨日期的延续、修改及结果关系；没有启用小事件的跨时间段短片段提前封存。
新封存的长事件保存来源起止时间，供按时间区间检索使用；旧事件未自动回填。

## 输入模型

`MemoryExperience` 表示一段经历，主要字段如下：

| 字段 | 当前用途 |
|---|---|
| `subject_id` | 匠石实例作用域；同一批经历必须属于该主体 |
| `text` | 经历原文，写入层不主动改写；内部代谢可以分析和封装事件 |
| `objects` | 对象称呼到对象 ID 的映射，可包含未在原文中出现或未说话的对象 |
| `interlocutor` | 该历史经历段的对话/互动对象 ID，不表示当前回忆查询的对话人 |
| `source_ids` | 事实、活动或认知等来源 ID |
| `occurred_at` | 经历发生时间；为空时事件时间回退到摄入时间 |
| `segment_id` | 匠石经历段标识，用于写入回执关联 |
| `origin` | `external`、`internal`、`dream` 等来源标签 |

`MemoryBatch` 按顺序携带多段经历。空文本会记入 `errors` 并跳过；当前批次中剩余有效经历会以空行拼接为一次代谢输入。合并对象和来源集合的同时，`SubSegment` 会保留每段原文、对象映射、段 ID 和历史对话对象，以免只用整批对象并集而造成事件归属串扰。

## 写入主流程

1. `REMSPipeline.ingest_batch` 校验并合并有效经历。
2. `MetabolismService` 处理输入边界和未封存内容。
3. `EventService` 默认封存完整长事件，同时生成摘要、角色、对象事实与情绪等信息。
4. 已封存事件写入事件仓储，并由 `RecallPipeline.index_event` 默认基于 L0 建立索引；L1 向量路径保留作对照，详见[回忆](recall.md)。
5. `stored_marks` 将匠石 `segment_id` 对应到本轮封存的事件 ID；尚未封存的内容通过 `unclosed_count` 反映。

一次输入不保证立刻形成一条封存事件：边界检测和代谢会决定如何封存，未完成内容会保留在未封存存储中。

来源去重不会把不同来源的相同表述当成重试；来源片段 ID 在缓冲和事件中持久化。
`SubSegment` 与 `BufferSentence` 携带源日期和 source_ids，缓存重建保留这些字段；
`Event.source_dates` 通过已有 recall_metadata JSON 保存。
回忆日期锚点默认中文，可配置英文；多来源日期写明区间，相对日期保留原始语境。

记忆摘要按实际 Unicode 字符数验收（英文空格及标点也计数）。L1 超预算时先用一次
调用生成按信息重要性排序的简短事实，程序在预算内组装完整句子，不截断单条事实。
若仍无有效摘要，再允许最后一次明确字符/词数预算的修复；仍失败报错，源材料不消费。
修复最多两次，不无界重试。后级必须变短、符合预算并遵守双熔断，
无效后级不发布，不强求生成十级。对象事实采用同样的长度校验。

L0→L1 的独立预算配置为 `summary_l1_retention_ratio`，默认保留三分之一，
例如 2000 字符对应 L1 上限 666 字符；不再乘旧摘要预算份额 0.4，
也不受角色数量、情绪、白描、装饰的预算分配影响。
极短文本沿用摘要熔断保底，但预算不超过原文长度。比例是长度预算，不是语义保留率；
模型不需要填满预算。环境变量为 `REMS_SUMMARY_L1_RETENTION_RATIO`。
后级摘要暂沿用现有递减规则；分阶段机制及其后台启动方式见[提炼说明](multistage-memory-refinement.md)。

## 事件与对象归属

事件由 `Event` 模型承载，包含 `content_raw`、多级 `summaries`、主体 ID、来源 ID、发生/创建时间、对象角色快照和 `interlocutor_attributions` 等信息。历史对话人归属按来源经历段记录；批次级单一 `interlocutor` 不能替代段级归属。

记忆模型还包含基本/抽象事件标记、事件状态和墓碑字段。`tombstone` 是逻辑标记路径；它用于让事件在审计数据中保留并从常规回忆中排除。不要把墓碑化与物理删除混为一谈。

## 当前存储

表定义见 `src/rems/storage/database.py`。常见表包括：

- `events`：事件主体、原文、摘要、时间、状态及生命周期字段。
- `roles`、`white_painting_entries`、`object_memory_entries`：对象/角色信息及其与记忆材料的关联。
- `event_tier1`：事件一级摘要等检索文本。
- `unclosed_events`、`shadow`：未封存事件和代谢上下文数据。
- `stored_marks`：输入段到封存事件的写入回执关系。
- `recall_traces`：启用时记录的查询和命中观测信息；不作为事件生成输入。
- `object_portraits` 及相关对象画像表：启用画像服务时保存的对象画像数据。

向量集合名由基础集合名与 `recall_embedding_version` 组合。更换嵌入模型/维度时，应评估版本号并重建索引，避免不同向量空间的数据混用。

## 遗忘相关的写入字段

事件保存 `activation_energy` 和 `forgetting_factor`。当前事件服务会从情绪唤醒度得到激活能量，并以配置 `recall_activation_gain` 计算初始遗忘因子；回忆阶段的时间衰减和命中强化见[回忆机制](recall.md#可及性近期通道与长期通道)。当前这套机制影响可检索概率和排序，不意味着系统按该因子定期物理删除事件。
